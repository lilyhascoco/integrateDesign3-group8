# 任务四：聚类驱动初始布局

## 实现目标与接口

新增 `ClusteringPlacement`，实现 `InitialPlacement::run(const PlacementDB&, PlacementState*)`。
复用 BookShelf 解析和 PlacementState，坐标统一保存为单元左下角；内部簇位置使用中心坐标。
固定单元不参加合并，保留位置、方向和固定类型。初始布局不做合法化，不保证无重叠或对齐行/站点。

## 算法

1. 每个可放入 core 的可移动单元独立成簇。超大单元保留输入位置、计入 skipped；命令行边界检查失败时返回非零退出码，不伪装成成功。
2. 对每条网去重所属单元。对 d 个不同单元的网，d<=32 时为每对单元累积 `net.weight/(d-1)`；同一单元多个管脚不重复增加聚类权重。
3. d>32 时用按单元 ID 排序的环近似，每条环边贡献 `net.weight/2`，保持每个端点在近似图中的加权度与完整图相当。它是为本课程规模采用的启发式，不能精确保持每个割或每一对连接强度。所有网仍用于最终 HPWL。
4. 用最大堆选择当前连接权重最大的可合并簇对，合并成员、累加面积与外部连接权重，以面积加权更新质心；零面积簇用成员数加权。版本号使旧堆项失效。每簇默认最多64个单元。
5. 达到目标簇数，或没有可合并连接时停止。默认目标是 `ceil(可放置单元数/32)`；受成员上限和断连影响，实际簇数可能更多，程序输出实际值。
6. 在 core 中按规则网格分散各簇，作为粗布局锚点，避免输入位置都在原点导致簇塌缩。执行20轮同步连接加权位置更新，保留10%的相对锚定权重并计入固定终端的连接吸引。锚定是启发式，不代表求解全局最优。
7. 以簇面积和 core 长宽比确定簇内矩形，再按成员数量划分网格槽位，按 ID 放置成员。最后根据单元尺寸将左下角裁剪到 core 内。

簇的质心在合并阶段按面积更新，粗布局阶段会重新安排位置，这是为原始单元坐标相同的数据补充的必要步骤。网格槽位数可能略多于成员数；单元尺寸不一致，且不同簇矩形可能相交，因此不能把槽位等同于无重叠合法位置。

## 性能与面积控制

没有构造全体单元的 N×N 矩阵。图构建代价为各网去重排序加小网的平方枚举、大网的线性环边；稀疏邻接表更新使用有序 map，堆操作为对数时间。实际合并复杂度依赖图结构、簇大小和堆中失效项数，不声称算法整体为 O(N log N)。最大成员数限制簇规模；宏块面积进入簇面积和矩形尺寸计算，但当前没有严格的最大簇面积阈值。

## HPWL 口径修正

BookShelf `.nets` 的偏移相对单元中心，因此使用：
`pin_x = lower_left_x + width/2 + offset_x`，y方向同理。
本次同步修正公共 HPWL 评估器及局部模拟退火的局部 HPWL，防止两者评价不一致。
仓库原 sample 的正偏移仍按相同公式解释，不为小样例单独切换口径。

## 编译与运行

通用 Linux 环境：

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j 4
ctest --test-dir build --output-on-failure
./build/placer benchmarks/sample/sample.aux --method compare --no-sa
./build/placer benchmarks/adaptec1/adaptec1.aux --method compare --seed 42 --no-sa --output build/adaptec1_cluster.pl
```

本机 Windows（本机配置和便携工具不随Git提交，其他电脑请安装CMake及C++17编译器，按上面的通用命令构建）：仓库旁边已放置官方便携 CMake 3.31.8，避免原 CMake 的运行库入口点错误。
在 VS Code 用“文件→打开文件夹”打开仓库目录；按 Ctrl+Shift+B 编译。
选择“终端→运行任务→Run sample comparison”或“Run adaptec1 comparison”运行。
任务显式使用本机 `C:/Users/Lenovo/mingw64/bin/g++.exe`（GCC14.2），不会调用 PATH 中旧的 Strawberry GCC3.4.5。
`.vscode/tasks.json` 是本机路径配置，给组员使用前需要按其编译器位置调整。

PowerShell 手动运行：

```powershell
$env:PATH = "C:/Users/Lenovo/mingw64/bin;" + $env:PATH
./build/placer.exe benchmarks/adaptec1/adaptec1.aux --method compare --no-sa --output build/adaptec1_cluster.pl
```

参数：
- `--method random|cluster|compare`：默认random；compare先输出随机结果，再输出聚类结果。
- `--seed 42`：随机布局和模拟退火固定随机种子；聚类本身确定性运行。
- `--clusters N`：目标簇数，0使用默认值。
- `--max-cluster-cells N`：单簇成员上限，必须为正数。
- `--no-sa`：只比较初始化，建议用于任务四实验。
- `--check-only`：解析并报告数据，不执行布局。
- `--output file.pl`：导出初始布局，compare模式导出聚类结果；即使随后执行退火，导出的仍是退火前初始布局。

默认保留原来的模拟退火后续流程；compare模式只对聚类结果继续退火，不是两种全局布局的对比。

## 验证范围与结果解读

测试覆盖强连接优先合并、成员上限、确定性、非零core原点、边界、固定单元、断连图、高扇出近似、超大单元、空设计及已知正确值的中心偏移HPWL。
实际结果见 `实验结果.md`。Windows Release 编译已经运行验证；未声称在 Linux 上实测。
拥挤指标沿用原随机方法的64×64 bin需求超容量之和，除以可移动面积。
它包含core内固定单元需求，只是密度溢出的代理量，不是精确几何重叠面积，也不能证明合法化可行。
HPWL更低可能伴随更严重的拥挤，应同时比较运行时间与该指标。单个算例、单个随机种子的结果不代表所有电路。
